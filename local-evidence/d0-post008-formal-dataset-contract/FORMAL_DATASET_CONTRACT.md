# D0-POST-008 Formal Dataset Contract

## Status

FROZEN DESIGN CONTRACT

This document defines the construction and governance requirements for
the future D0-POST-008 formal evaluation dataset.

This document does NOT contain formal evaluation examples.

This step does NOT authorize formal dataset construction, inspection,
model scoring, or formal execution.

---

## 1. Purpose

The POST-008 formal dataset will provide a fresh, sealed evaluation
artifact for comparing the accepted baseline checkpoint against the
single preselected candidate checkpoint.

The dataset exists exclusively for formal evaluation.

It must not become a development artifact.

---

## 2. Freshness

The POST-008 formal dataset must be newly constructed.

It must not reuse rows from any historical formal evaluation dataset.

Historical formal datasets must not be opened for the purpose of
constructing POST-008.

No formal expected response from an earlier stage may be copied into
POST-008.

---

## 3. Development Isolation

Before formal exposure begins, POST-008 formal rows must not be used
for:

- training;
- retraining;
- fine-tuning;
- candidate selection;
- checkpoint selection;
- prompt development;
- tokenizer development;
- architecture modification;
- scoring-code modification;
- threshold tuning;
- adjudication-policy tuning;
- debugging model behavior.

The candidate checkpoint must already be fixed independently of the
POST-008 formal dataset.

---

## 4. Dataset Schema

The formal dataset will use JSON Lines.

Each row must contain the minimum fields required by the frozen
POST-008 scoring dependency.

The eventual schema must be validated before sealing.

No field may exist solely to leak the expected answer to the model.

Expected/reference outputs may be available to the scoring layer but
must never be inserted into model-visible input.

---

## 5. Evaluation Coverage

The dataset must exercise the capabilities that POST-008 is intended
to measure.

Coverage must include multiple independent evaluation categories
rather than repeated variants of one prompt pattern.

Category allocation must be frozen before the completed formal dataset
is scored.

No category may be added, removed, or reweighted after observing model
performance.

---

## 6. Difficulty

The dataset should contain a deliberate distribution of difficulty.

It must not be constructed specifically to favor either the accepted
baseline or candidate.

Examples must be selected using capability requirements, not known
checkpoint behavior.

---

## 7. Independence

Formal examples must not be generated by querying the candidate and
then designing rows around its successes or failures.

Formal examples must not be generated by querying the baseline and
then designing rows around its successes or failures.

Neither checkpoint may be used to preview, filter, rank, reject, or
rewrite formal rows before sealing.

---

## 8. Expected Responses

Expected/reference responses must be established independently of
candidate output.

They must not be printed during formal execution.

They must not be exposed to the model.

They must not be modified after either checkpoint has been scored.

---

## 9. Dataset Construction Boundary

Dataset construction must occur in a separate governed step.

The target path is:

`ml/data/d0_post008_formal.jsonl`

The dataset must not be created by this contract-freeze step.

After construction, its SHA-256 identity must be frozen before formal
execution authorization.

---

## 10. Sealing

Once the formal dataset is finalized:

1. validate its schema;
2. validate row count;
3. validate category allocation;
4. verify development isolation;
5. compute SHA-256;
6. freeze dataset identity;
7. prohibit modification;
8. prohibit replacement;
9. prohibit candidate-dependent filtering.

Any content change after sealing creates a different evaluation
artifact and invalidates the previous identity.

---

## 11. Exposure Boundary

Formal exposure begins immediately before the first formal row is
loaded by the authorized execution path.

A create-once formal exposure marker must be persisted before loading
formal rows.

After formal exposure begins:

- rerunning the formal comparison is forbidden;
- replacing the dataset is forbidden;
- changing expected responses is forbidden;
- changing the candidate is forbidden;
- changing scoring dependencies is forbidden;
- changing adjudication rules is forbidden.

Failure after exposure must be preserved as evidence.

---

## 12. Scoring Order

The future formal execution must preserve the frozen lifecycle:

1. create formal exposure marker;
2. load sealed formal rows;
3. score accepted baseline;
4. persist baseline result;
5. score candidate;
6. persist candidate result;
7. reload persisted results;
8. compare persisted results;
9. persist final adjudication.

The baseline result must exist before candidate scoring begins.

The comparator must consume persisted results.

---

## 13. One-Time Execution

Formal execution authorization must permit exactly one POST-008 formal
comparison.

Authorization creation alone must not start exposure.

Arming alone must not start exposure.

Formal exposure must make the execution non-repeatable.

---

## 14. No Training Authorization

Formal evaluation does not authorize:

- training;
- retraining;
- fine-tuning;
- additional candidate creation.

Any later training decision requires a separate stage and separate
authorization.

---

## 15. Formal Result Interpretation

A successful execution does not automatically mean the candidate is
accepted.

Acceptance depends on the separately frozen adjudication policy.

The formal dataset itself must not be changed in response to the
result.

---

## 16. Current Boundary

At the time this contract is frozen:

- POST-008 formal dataset does not exist;
- POST-008 formal dataset has not been opened;
- no real checkpoint has been loaded for POST-008;
- no real POST-008 inference has occurred;
- no real POST-008 scoring has occurred;
- no POST-008 formal exposure has started;
- real formal execution remains disabled;
- formal execution is not authorized.

The next step may define the exact dataset specification and
construction plan.

It must not perform formal model scoring.
